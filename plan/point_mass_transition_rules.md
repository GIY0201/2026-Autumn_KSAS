# 질점 행동 전환 확인과 데이터 생성 규칙 후보

날짜: 2026-09-08. 사용자 요청: 직선→선회, 상승→순항, 하강→착륙을 짧은 질점 궤적으로 확인한 뒤 생성 규칙의 근거로 사용한다.

상태: **대표 사례의 수치적 연결 확인 완료 / 전체 운용 범위·학습데이터 생성 미완료**.

## 무엇을 확인했는가

기존 `point_mass.py`와 제어기, 일반 생성 profile은 변경하지 않았다. 별도 `transition_probe.py`가 수평속력·수직속도·선회율 목표를 점진적으로 바꾸고, 기존 `advance_point_mass`로 위치를 적분한다. 시계열 속도에서 가속도·jerk를 독립 차분하며 위치 차분과 속도도 비교한다. 위치를 목표 고도에 대입하거나 착륙 순간 0으로 덮어쓰지 않는다.

공기력·추력·회전 모멘트·지면 접촉·실기체 안정성을 확인한 시험은 아니다. Gazebo 경계 계산과 별도이며, 아래 제한값의 물리적 타당성이 검증됐다는 뜻이 아니다. 세 객체는 서로 다른 시험 조건을 같은 질점 integrator에 넣었으며, 객체별 동역학을 새로 식별한 것이 아니다.

## 명령의 연결 방식

전환 진행률 `u=t/T`에 대해 `S(u)=10u³−15u⁴+6u⁵`를 사용한다.

`q(t)=q_start + (q_end−q_start) S(u)`이며, `q`는 수평속력·수직속도·선회율이다. 다항식의 시작/끝에서 1차와 2차 미분이 0이다. 가속도를 0으로 끝내는 것이 아니라 **목표 변수의 변화율**을 0으로 끝낸다는 뜻이다. 일정 선회 중의 구심 가속도와 공간상 jerk는 남을 수 있다.

기존 integrator가 한 스텝 동안 선회율을 고정하는 특성 때문에 속력 목표는 스텝 끝, 선회율은 스텝 중간에서 평가한다. 끝점 선회율을 그대로 넣은 첫 진단은 시간 간격 차이에 따른 경로 오차가 0.231 m였으므로 실패로 보존했다. 중간 시점 적용 후 동일 0.1 m 기준을 통과했다. 기존 integrator 자체는 수정하지 않았다.

## 전환시간에서 확인된 제약

이 다항식은 최대 `S'(u)=1.875`이므로 하나의 속도 성분 변화에는 다음 필요조건이 있다.

`T ≥ 1.875 × |속도 변화량| / 해당 가속도 한도`

VTOL 0→20 m/s를 10초에 연결하면 최대 접선 가속도는 **3.75 m/s²**다. 진단에서는 전환만 한도 4 m/s²로 명시하여 통과시켰다. 2 m/s² 조건의 실패도 별도로 실행했다. 10초·20 m/s·2 m/s²를 동시에 이 곡선으로 만족시킬 수는 없다. 2 m/s²를 유지하면 이 곡선에서 10초간 가능한 속력 변화는 최대 약 10.67 m/s다.

이는 특정 다항식과 일정한 양 끝 상태에 대한 결과다. 모든 전환 곡선의 전역 최소시간은 아니다. 또한 이 식만으로 선회/상승을 포함한 전체 벡터 가속도·jerk 한도가 보장되지 않는다. 실제 결합 궤적에서 함께 확인한다.

## 합의한 생성 규칙 — 2026-09-08

사용자가 아래 방식에 동의했다. 객체별 기동 범위와 단계 연결의 부드러움 설정을 분리하며, 진단용 수치를 실제 기체 한계로 승격하지 않는다. 규칙 합의와 생성기 구현 완료는 별개다.

1. **전환은 위치가 아니라 운동 목표를 연결한다.** 이전 위치·속도를 이어받고 새 위치는 적분한다. 독립 구간의 좌표를 억지로 붙이지 않는다.
2. **시간은 끝 상태와 가감속·jerk 설정에 맞춘다.** 설정 초과를 해결하려고 한도를 자동으로 올리지 않는다. 조정 가능한 진입·회복 시간을 늘리되, 전체 600초를 넘거나 고도·기동 제약을 충족하지 못하면 해당 조합을 거부한다. 합의된 VTOL 모드 전환 시간은 이륙 측 20초·착륙 측 10초로 유지하며, 착륙 측의 잔여 감속은 전환 뒤에 별도로 배정한다. 불가능한 목표를 clipping한 결과를 성공으로 표시하지 않는다.
3. **가속·선회·상승의 결합을 확인한다.** 수평 접선/법선 가속도의 합성, 수직 가속도, 전체 벡터 jerk를 함께 검사한다.
4. **목표 고도 전에 상승률·하강률 완화를 시작한다.** 감속 동안의 고도 변화를 미리 계산한다. 높이에 도착한 뒤 수직속도를 갑자기 0으로 만들지 않는다. 현재 사례의 초기 높이는 이 목적에 맞춰 역산했다.
5. **헬기 최종 저속 착륙 시작 높이는 10 m.** 이는 사용자 채택값이다. 10 m 진입 이전의 하강률 완화도 별도 연결해야 한다. 이번 사례는 10 m 진입 때 이미 −1 m/s인 조건이다.
6. **통과 범위를 확대 해석하지 않는다.** 위 10조건의 성공으로 이전 속력표 전체, 좌우 반전/S자/나선, 모든 최소·최대 조합이 검증됐다고 하지 않는다.
7. **전체 Episode에서도 다시 검사한다.** 지상 0→이륙→선택 기동→착륙·정지, 600초 이하, 고도 제약과 단계당 한 기동을 함께 충족해야 한다.
8. **학습용과 진단용 출력을 분리한다.** 이 결과는 evaluation-only다. 이후 전체 Episode 생성 시 기존 5 Hz 관측·truth 분리와 Episode 단위 데이터 분할을 유지한다.

## VTOL 착륙 측 연결 — 첫 시나리오 합의

`고정익 하강 → 80 m에서 수평 직선 정렬 완료 → 10초 회전익 전환·감속 → 필요한 잔여 감속 → 호버링 → 수직 착륙`

- 첫 시나리오의 착륙 측 전환 고도는 80 m로 사용한다. 이륙 고도를 자동 복사한 것이 아니라 이번 제안에 대한 사용자 동의로 채택한 시뮬레이션 조건이다. 모든 기체의 성능값이나 모든 시나리오의 유일한 고도로 일반화하지 않는다.
- 전환 시작속도는 직전 구간의 실제 종료속도를 이어받는다. 10초 종료 시 속력 0을 강제하지 않으며, 양쪽 구간의 위치·속도·가속도를 연속적으로 연결한다.
- 잔여 감속도 고도·진행 방향을 유지하고, 정지한 뒤 수직 착륙을 시작한다. 모드 변경 시 감속 곡선을 초기화하거나 순간 정지시키지 않는다.
- 감속 궤적의 이동 거리를 포함해 전환 시작 위치를 정한다. 착륙 지점 위에 도달한 뒤 수평 위치를 강제로 고정하지 않는다.
- 잔여 감속과 호버 안정화 시간도 전체 600초에 포함한다. 제어기 개발·실기체 안정성 검증은 이번 합의의 범위가 아니다.
- 기존 `vtol_transition_in`의 100 m·20→0 m/s·10초 진단은 과거 비교용 fixture로 보존한다. 이번 80 m·잔여 감속 포함 시나리오를 구현하거나 검증한 것으로 간주하지 않는다.

## 남은 단계

가감속·jerk를 생성용 부드러움 설정으로 분리하는 방식과 첫 VTOL 착륙 측 전환 고도 80 m는 합의했다. 구체적인 수치 설정은 기존 진단값이 초기 후보이며, 객체별 속력 조합·잔여 감속 시간·종료 상태 허용오차와 함께 실행 설정으로 명시해야 한다. 이후 최대 600초 전체 시나리오 연결·저장 형식 지원 → 소량 생성 확인 → 학습데이터 생성 순서로 진행한다. 이번 합의 기록에서 코드·설정·데이터·UI는 변경하지 않았다.
