# 설계·계획 문서 지침

- [project_structure.md](project_structure.md), [생성 설계](data_generation_v1_design.md), [모델 설계 인계](model_design_handoff.md)에서 해당 작업 범위를 확인한다.
- 추가 결정이 필요하다고 판단하기 전에 [결정 대조표](decision_reconciliation.md)를 확인한다. 초반 합의와 이후 변경을 구분하고, 누락된 합의를 새 설계로 취급하지 않는다.
- 상세 설계·의사결정·근거·미확정 목록은 여기에 둔다. `AGENTS.md`에는 반복적으로 지킬 규칙과 읽을 문서만 남긴다.
- 각 문서에 범위·상태·날짜·합의 출처를 적는다. 합의, 설계 제안, 미확정, 이전 점검 기록, 실제 구현/실행 결과를 분리한다.
- 다른 작업의 인계는 출처와 승인 범위를 남긴다. 미확정 수치나 인계를 구현 승인으로 바꾸지 않는다.
- 기존 GRU 기준과 RED-SDS 합의의 차이를 드러낸다. 기준 문서 전환은 사용자와 범위를 확인한 뒤 이유·영향을 기록한다.
- 새 규칙은 해당 책임 폴더에 배치하고 루트에 복사하지 않는다. 자식 지침은 부모를 보완하며 `configs/`, `tests/`에 동일 파일을 기계적으로 복제하지 않는다.
- 출처 주장은 원문·저자·연도·DOI를 확인한다. 이전 감사 결과는 당시 기록으로 표시하고 재실행하지 않은 수치를 새 검증 결과로 쓰지 않는다.
- 흐름은 간단한 예시/도식으로 먼저 설명한다. 계획의 검증 항목을 통과한 결과처럼 쓰지 않는다. 기존 도식은 GRU 기준의 자료로 보존한다.
