# 고정익·헬기·VTOL 운동 시나리오 통합 명세

작성일: 2026-09-07  
갱신일: 2026-09-08  
상태: 시나리오 구성과 현재 생성 설정을 함께 정리한다. 전체 비행 생성기는 연결되어 있으며, 실행 기록은 [생성기 통합 문서](scenario_generator_integration.md)에서 확인한다. 여기의 설정값은 실제 기체의 성능 한계가 아니라 연구용 생성 규칙이다.  
합의 출처: 현재 작업의 사용자 지시와 후속 승인. 특히 단계별 기동 하나 선택, 헬기 96종, VTOL 64종, VTOL 전환 중 선택 기동 제외, 이륙 측 전환 20초·착륙 측 10초, 헬기·VTOL 초기 수직 이륙 고도 80 m 및 첫 VTOL 착륙 측 전환 고도 80 m에 관한 최신 대화를 반영한다.

표기 변경: 사용자 승인에 따라 조합표를 한글 이름 중심의 한 시나리오당 한 행으로 바꿨다. 기존 내부 ID는 각 행의 HTML 주석에 보존한다. 기동 조합과 수치 규칙은 그대로다.

## 1. 문서의 목적과 범위

고정익 무인기, 헬기, Standard VTOL 무인기의 비행을 지상 출발부터 착륙·정지까지 하나의 연속 Episode로 구성한다. 상승에서 하나, 순항 또는 수평 이동에서 하나, 하강 또는 접근에서 하나씩 기동을 선택한다.

```text
공통 출발 과정 → 상승 기동 1개 → 중간 기동 1개 → 하강·접근 기동 1개 → 공통 착륙 과정
```

복잡한 움직임을 한 Episode에 몰아넣지 않는다. 단순 직선 비행과 호버링도 정식 선택지다. 같은 기동 조합에서도 출발 방향·선회 방향·속도를 바꾸어 다양한 데이터를 만든다. 현재 seed가 바꾸는 항목은 6절에 정리했다.

- 최종 연구용 궤적 표현은 객체별 제약을 갖는 3D 질점 모델이다. 기체 자세·모터·조종면·센서 내부 장치의 정밀 재현을 목표로 하지 않는다.
- Gazebo 식·계수와 별도 참조 모델 계산은 운용 수치를 검토할 때 참고한다. 현재 전체 비행 생성기가 Gazebo를 실행하거나 실측 운동을 그대로 재현하는 것은 아니다. 이 문서의 기동 목록이나 사용자 지정 각도를 Gazebo가 도출한 결과로 표시하지 않는다.
- 이번 통합 대상은 세 객체다. 기존 쿼드콥터 구현을 삭제하거나 이번 문서에 새로 포함하지 않는다.
- 기존 60초 진단 데이터, 코드, 설정, 계약, 8088 viewer, 원본 및 결과는 이 문서 작성으로 변경하지 않는다.
- 아래 조합표는 시나리오 카탈로그이며 실제 생성 성공, 기체 성능 한계 또는 안전 보장을 뜻하지 않는다.

### 관련 문서와 읽는 순서

1. 이 문서: 최신 객체별 시나리오 구성과 선택 기동, VTOL 전환 규칙.
2. [질점 전환 명세](point_mass_migration_design.md): 단계별 구현 경계와 기존 고정익 합의.
3. [결정 대조표](decision_reconciliation.md): 초반 결정 및 변경 이력. 초기 60초 기록과 후속 최대 600초 설계를 구분한다.
4. [Gazebo 최소 제약 근거](gazebo_minimum_constraints.md), [독립 참조 함수 작업 기록](gazebo_reference_implementation.md): 모델 근거와 별도 수치 추출 작업. 진행 상태는 해당 문서를 따른다.
5. [생성용 참조 조건 선별](motion_condition_selection.md): 세 객체의 목표 충족 조건 60개(유지 기동 후보 57 + 전환 참고 3), 미충족 39개와 생성기 연결 공백. 실제 생성용 전역 상한으로 확정한 표는 아니다.
6. [기동별 확장 참조 범위](gazebo_maneuver_ranges.md): 2026-09-08 요청으로 고정익·헬기·VTOL의 시험 격자를 확장한 작업. 최소·최대 요약과 조건별 응답을 함께 기록하며 실제 완료 상태는 해당 문서를 따른다.

이 문서는 위 문서 전체를 대체하지 않는다. 시나리오에 관한 최신 합의를 한곳에 모으고, 나머지 연구·데이터 경계는 보존한다.

## 2. 공통 규칙

| 항목 | 규칙 | 해석 |
|---|---|---|
| 시나리오 길이 | 이륙·전환·기동·착륙·정지까지 최대 600초 | 반드시 600초를 채우는 것이 아님 |
| 출발·종료 | 지상 고도 0 m에서 출발하고 지상에 착륙·정지 | 출발점과 착륙점의 XY 일치는 별도 결정이며 자동 강제하지 않음 |
| 헬기·VTOL 초기 이륙 | 지상 0 m에서 수평 위치를 유지하며 80 m까지 수직 상승 후 초기 호버링 | 이전의 100 m안을 대체한 사용자 설계값. 고정익 및 착륙 측 고도 기준과 구분 |
| 이번 확인용 운용·순항 목표 고도 | 고정익 300 m, 헬기·VTOL 500 m | 고정익만 최신 요청으로 하향. 헬기는 중간 수평 이동·체공 고도에 해당하며, 600초 내 완주 확인을 뜻하지 않음 |
| 고도 상한 | 기존 설계의 최대 1,000 m 상한 보존 | 전역 상한과 이번 객체별 운용·순항 목표는 구분 |
| 좌표·단위 | Local ENU: X=East, Y=North, Z=Up; m, s | 3D 궤적 하나를 XY/XZ/YZ/3D로 표시 |
| 관측 간격 | 5 Hz, 0.2초 간격 | 전체 비행은 가변 길이로 저장·재생한다. 기존 60초·301시점 데이터는 별도로 보존한다 |
| 환경 | 단일 객체, 신규 합성은 무풍 | GPS·카메라·지형·충돌 회피·다물체 상호작용은 이번 설계에 추가하지 않음 |
| 기동 선택 | 상승·중간·접근 단계마다 종류 하나 | 한 단계에 선회→S자→나선을 임의로 나열하지 않음 |
| 연속성 | 이전 상태를 이어받아 위치·속도를 연속 계산 | 위치·속도 순간 재설정, 순간 방향 반전 금지. 가속·선회율도 부드럽게 변화 |
| 데이터 분할 | 긴 원본 Episode에서 기동 구간을 파생 | 같은 원본 Episode의 조각을 TRAIN과 평가에 나누지 않음 |
| 정보 경계 | 기동 명령·모드·truth는 평가/검토용 | 관측 입력에 내부 상태나 미래 기동 정보를 누출하지 않음 |

### 2.1 기동 하나의 내부 구조

```text
안정된 시작 상태 → 부드러운 진입 → 선택 기동 유지 → 부드러운 회복 → 다음 단계의 시작 상태
```

- 안정 상태가 반드시 수평 직진이나 가속도 0이라는 뜻은 아니다. 일정 속도·상승률의 비행도 해당한다.
- S자의 좌우 곡선과 정지 후 재출발의 감속·호버링·가속은 해당 기동 내부 과정이다.
- 단계 연결을 위한 감속·가속·수평 비행 회복은 추가 선택 기동으로 세지 않되, 시간과 궤적에는 포함한다.
- 기동 유지 부분만 잘라내지 않고 진입·회복 구간도 보존한다. 단계 기록은 검토에 사용하며 미래 기동 정보를 학습 입력에 넣지 않는다.

### 2.2 움직임 용어

| 용어 | 위치 궤적 기준 정의 |
|---|---|
| 직선 상승·하강 | 수평 이동을 동반하는 경사 직선 경로. 수직 이동과 다름 |
| 수직 상승·하강 | 수평 위치를 유지하고 고도를 변경 |
| 선회 | 한 방향으로 정해진 방향 변화량만큼 돌아 빠져나오는 기동 |
| S자 | 반대 방향의 곡선을 부드럽게 연결하는 하나의 기동 |
| 원주비행 | 고도를 유지하면서 원형 경로를 지속적으로 따라가는 기동 |
| 나선 상승·하강 | 원형 경로를 지속적으로 따라가면서 고도를 변경 |
| 호버링 | 일정한 위치·고도를 유지하는 상태 |
| 정지 후 재출발 | 이동 → 감속 → 호버링 → 같은/다른/반대 방향으로 재가속 |

좌선회·우선회, 시계·반시계, S자의 시작 방향은 기동 종류가 아닌 변형 parameter로 관리한다. 원주·나선의 회전량과 일반 선회의 구체적인 경계 수치는 아직 정하지 않았다.

### 2.3 시나리오 ID 범례

문서의 시나리오 이름은 한글로 표시하지만, 코드·데이터와 대응할 때는 기존 내부 ID를 사용한다. 예를 들어 `F01-A`는 **고정익의 직선 상승 → 직선 순항 → 직선 하강**을 뜻한다.

| 부분 | 뜻 | `F01-A`의 해석 |
|---|---|---|
| 첫 문자 | 객체 종류: `F`=고정익, `H`=헬기, `V`=VTOL | 고정익 |
| 두 자리 숫자 | 상승·하강 기동의 조합 번호. 시간이나 실행 횟수가 아님 | `01`=직선 상승 + 직선 하강 |
| 마지막 문자 | 순항·중간 이동 기동. 객체별 대응이 다름 | 고정익의 `A`=직선 순항 |

#### 마지막 문자: 순항·중간 이동

| 문자 | 고정익·VTOL | 헬기 |
|---|---|---|
| A | 직선 순항 | 호버링 |
| B | 선회 순항 | 직선 이동 |
| C | S자 순항 | 선회 이동 |
| D | 원주비행 | S자 이동 |
| E | 사용하지 않음 | 원주비행 |
| F | 사용하지 않음 | 정지 후 재출발 |

예를 들어 `H10-F`는 **헬기 · 선회 상승 → 정지 후 재출발 → 직선 하강**, `V05-D`는 **VTOL · 선회 상승 → 원주비행 → 직선 하강**이다. 각 조합 앞뒤에는 객체별 공통 이착륙 과정이 붙으며, VTOL은 두 모드 전환도 포함한다. ID에는 속도·seed·실행 횟수가 들어 있지 않으므로 같은 ID로 서로 다른 Episode를 생성할 수 있다.

## 3. 고정익 무인기

### 3.1 전체 진행

```text
지상 정지: 고도 0 m
  → 지상 출발·이륙
  → 초기 직선 상승: 50 m까지, 유지 경로각 +3°
  → 선택 상승 기동 1개: 50 m 이후부터 목표 300 m까지, 최대 +10°
  → 선택 순항 기동 1개: 300 m 유지
  → 선택 하강·접근 기동 1개: 300 m에서 하강, 100 m 초과 구간
  → 100 m 진입 전에 착륙 방향 정렬·경로각 전환 완료
  → 저고도 직선 최종 접근: 유지 경로각 −3°
  → 착륙 회복·접지·감속
  → 지상 정지: 고도 0 m
```

지상 가속·이륙과 착륙 감속은 현재 생성 설정의 속도·가속도 제한으로 연결한다. 주요 설정은 7절에 정리했다. 활주로 시설, 착륙장 장치 또는 접촉 동역학의 정밀 모델을 새로 요구하지 않는다.

### 3.2 선택 기동과 고정 규칙

| 단계 | 선택지 | 조건 |
|---|---|---|
| 초기 상승 | 공통 직선 상승 | 50 m까지 이륙 방향 유지, 유지 경로각 +3° |
| 기동 상승 | 직선 / 선회 / S자 / 나선 상승 | 50 m 초과에서 상태 조건을 만족한 뒤 진입, 목표 300 m까지 상승 경로각 최대 +10° |
| 순항 | 직선 / 선회 / S자 / 원주비행 | 300 m 고도 유지. 공중에서 호버링·완전 정지하지 않음 |
| 하강·접근 | 직선 / 선회 / S자 / 나선 하강 | 100 m 초과에서 하강 경로각 크기 최대 10° |
| 최종 접근 | 공통 직선 하강 | 100 m 이하 유지 경로각 −3°, 저고도 선회·S자·나선 금지 |
| 착륙 | 공통 착륙 회복·접지·감속 | 지면 관통 또는 속도 순간 초기화 금지 |

- 최신 수정으로 **50 m까지 직선 상승, 이후 조건부 기동 허용**을 적용한다. 이전 상승 경계 100 m를 대체하며, 300 m는 선회 시작 고도가 아니라 운용·순항 목표다.
- 고도 50 m를 넘었다는 이유만으로 경로각·선회율을 순간적으로 바꾸지 않는다. 하강 경계는 기존 100 m를 유지하며 상승과 대칭으로 변경하지 않는다.
- 현재 기본 수평 목표속도는 30 m/s(108 km/h)다. seed에 따른 배율을 적용하면 28.5~30 m/s이며, 실제 기체의 검증된 최대 속력은 아니다. 지상 가속·flare·접지·정지에도 이 속도를 강제하는 것은 아니다. 상승·하강 중 총속력은 수직 성분까지 포함하므로 수평속도와 구분한다.
- 3°는 해당 구간의 **유지 경로각**이다. 지면 이탈·상승 종료·착륙 flare에는 연속 진입·회복이 필요하다. −3°를 접지 순간까지 강제하지 않는다.
- 경로각은 속도 벡터와 수평면 사이 각도이며 기체 pitch가 아니다.
- 현재 공중 최소 수평속도, 선회율, 가감속과 유지시간 설정은 7절을 따른다. 기존 테스트 설정의 수직속도 1 m/s 등을 새 한계로 채택하지 않는다.

## 4. 헬기

### 4.1 전체 진행

```text
지상 정지: 고도 0 m
  → 수직 이륙·초기 상승: 0 m → 80 m
  → 80 m에서 초기 호버링
  → 선택 상승 기동 1개: 80 m에서 목표 500 m까지
  → 선택 수평 이동·체공 기동 1개: 500 m 유지
  → 선택 하강·접근 기동 1개: 500 m에서 하강
  → 착륙 지점 위에서 감속·호버링
  → 수직 하강·착륙
  → 지상 정지: 고도 0 m
```

### 4.2 선택 기동과 고정 규칙

| 단계 | 선택지 | 조건 |
|---|---|---|
| 이륙 | 공통 0→80 m 수직 상승 → 80 m 초기 호버링 | 수평 위치 유지. 지상에서 순간적으로 공중 위치로 이동시키지 않음 |
| 상승 | 수직 / 직선 / 선회 / 나선 상승 | 하나 선택. 80 m 초기 호버링 이후 부드럽게 진입 |
| 수평 이동·체공 | 호버링 / 직선 / 선회 / S자 / 원주비행 / 정지 후 재출발 | 하나 선택. 수평 이동 기동은 고도 유지 |
| 하강·접근 | 수직 / 직선 / 선회 / 나선 하강 | 하나 선택. 공통 최종 착륙으로 연결 가능한 상태에서 종료 |
| 최종 착륙 | 호버링 → 수직 하강 → 접지·정지 | 선회·나선 하강을 지면까지 지속하지 않음 |

- 고정익의 상승 50 m·하강 100 m 및 3°·10° 규칙을 헬기에 일괄 적용하지 않는다.
- 초기 수직 상승은 모든 헬기 시나리오에서 80 m까지 수행한다. 선택 상승 기동은 이 공통 구간 뒤에 배치한다. 초기 호버링 진입 시 수직속도를 부드럽게 줄이며, 80 m로 위치를 순간 보정하지 않는다.
- 2026-09-08 사용자 채택: 헬기의 최종 저속 수직 착륙 구간은 지상 10 m부터 시작한다. 10 m 진입 전에 저속 상태로 연결하고 접지 전 수직속도를 연속적으로 0까지 줄인다. 구체적인 하강속도·전환시간은 이 고도 결정과 별개이며, 고정익 flare 고도나 VTOL 착륙 측 전환 고도에 적용하지 않는다. [전환 진단 및 후보 규칙](point_mass_transition_rules.md)을 참조한다.
- 80 m는 초기 이륙 완료·호버링 고도이며 순항 고도 상한이나 최종 착륙 호버링 고도가 아니다. 초기 상승과 안정화 시간도 전체 최대 600초에 포함한다.
- 직선 이동에서 수직 하강으로 연결할 때 수평 속도를 먼저 줄인다. 필요한 감속은 연결 과정이며 별도의 선택 기동으로 세지 않는다.
- 정지 후 반대 방향 이동은 감속 → 정지 → 재가속으로 구성한다. 속도 부호를 순간적으로 바꾸지 않는다.
- 위치만 사용하는 모델에서는 기체 기준 전진·후진·측면 이동을 별도 class로 구별하지 않는다. 공간상 이동 방향은 설정으로 구분한다.
- 위치가 변하지 않는 기수 회전은 별도 궤적 종류가 아니라 호버링으로 취급한다.
- 수직 하강과 수평 이동을 동반한 하강의 허용 수치를 동일하다고 가정하지 않는다. 회전익 기동에 고정익의 공중 최소 속도를 적용하지 않는다.

### 4.3 전체 조합표 — 96종

상승 4종 × 수평 이동·체공 6종 × 하강 4종 = **96종**이다. 대화에서 정한 `H` ID를 유지한다. 모든 시나리오에 4.1의 공통 이륙·호버링·최종 착륙을 붙인다.

## 5. Standard VTOL 무인기

### 5.1 전체 진행

```text
지상 정지: 고도 0 m
  → 회전익 모드로 수직 이륙·초기 상승: 0 m → 80 m
  → 80 m에서 초기 호버링
  → 순항 전환 20초: 고도 80 m·진행 방향 유지 목표, 직선 전방 가속
  → 전환 완료 후 선택 고정익 상승 기동 1개: 80 m에서 목표 500 m까지
  → 선택 고정익 순항 기동 1개: 500 m 유지
  → 선택 고정익 하강·접근 기동 1개: 500 m에서 하강
  → 하강·선회 종료, 수평 직선 비행으로 연결
  → 호버 전환 10초: 첫 시나리오는 고도 80 m·진행 방향 유지 목표, 직선 감속
  → 필요한 잔여 감속·안정화 → 착륙 지점 위 호버링
  → 회전익 모드로 수직 하강·착륙
  → 지상 정지: 고도 0 m
```

수직 이착륙과 두 전환 구간은 공통으로 두고 고정익 비행 구간에서 다양성을 만든다. 기본 카탈로그에는 전환 반복, 중간 회전익 기동 또는 회전익으로만 끝내는 별도 임무를 추가하지 않는다. Standard VTOL의 구성을 모든 tiltrotor·tailsitter에 자동 일반화하지 않는다.

| 순항 전환 | 공통 직선 전방 가속, 20초 | 고도 80 m·진행 방향 유지 목표, 선택 상승·하강·선회·S자·나선 기동을 겹치지 않음 |
| 고정익 상승 | 직선 / 선회 / S자 / 나선 상승 | 전환 완료 후 하나 선택 |
| 고정익 순항 | 직선 / 선회 / S자 / 원주비행 | 고도를 유지하며 하나 선택, 호버링·완전 정지 없음 |

| 최종 착륙 | 호버링 → 공통 수직 하강·접지 | 수평 이동을 마친 상태에서 착륙 |

**최신 확정: 전환 중 선택 기동은 넣지 않는다.** 직전 대화에서 제안했던 ‘전환하면서 선회·상승 기동에 진입’은 사용자가 제외했다. 전환 자체의 전방 가속·감속은 유지한다.

- 이 분리는 우리 시나리오의 단순화 규칙이다. 실제 고정익 양력·제어 효과가 전환 완료 순간에 갑자기 생긴다는 의미가 아니다.
- 고도 유지 **목표**는 의도적인 고도 변경 명령을 넣지 않는다는 뜻이다. 계산된 Z 좌표를 매 순간 덮어쓰는 방식으로 구현하지 않는다.
- 고정익 하강은 지면까지 이어지지 않는다. 하강률·선회율을 줄이고 전환 가능한 수평 직선 상태로 연결한 뒤 호버 전환을 시작한다.
- 전환 시작 위치와 최종 호버 위치는 다르다. 감속 중 전진 거리와 고정익 접근 경로를 함께 고려한다.
- 모드 변경 순간에 속도를 0으로 설정하지 않는다. 회전익 전환과 최종 호버링 도달을 구분하여 연속 계산한다.
- 고정익의 상승 50 m·하강 100 m 및 3°·10° 규칙을 VTOL의 이착륙·전환에 자동 적용하지 않는다. VTOL 고정익 구간의 수치 범위도 해당 모델 근거로 별도 선정한다.
- 초기 수직 이륙은 모든 VTOL 시나리오에서 80 m까지 수행하고, 80 m 초기 호버링 후 순항 전환을 시작한다. 선택 고정익 상승 기동은 20초 순항 전환을 마친 뒤 시작한다. 초기 상승·안정화 시간도 전체 최대 600초에 포함한다.
- 전환 시간은 이륙 측 20초, 착륙 측 10초이며 양쪽 전환의 목표 고도는 현재 설정에서 80 m다. 착륙 측 80 m는 첫 시나리오에 대해 승인한 값을 현재 기본 설정으로 사용한다. 시작속도는 직전 구간에서 이어받고 10초 후 완전 정지를 강제하지 않는다. 가감속·jerk의 현재 생성 설정은 7절, 설계 근거는 [합의한 전환 규칙](point_mass_transition_rules.md)을 참고한다.

#### 전환 시간 — 사용자 합의, 2026-09-08 갱신

2026-09-08 사용자 승인으로 이륙 측만 10초에서 20초로 늘렸다. 호버링에서 수평 0→20 m/s로 가속하는 진단 곡선의 요구 가속도를 낮추기 위한 변경이다. 착륙 측 10초는 변경하지 않으며, 20 m/s 및 가감속 한도는 기체 성능 한계로 확정하지 않는다.

|---|---:|---|

| 고정익 → 회전익: 호버 전환 | 10초 | 고도·진행 방향 유지 목표의 직선 감속 |

- 두 전환의 합계 **30초는 전체 최대 600초에 포함**한다. 실제 기체의 고정 성능값이나 Gazebo에서 확인한 결과가 아니라 **사용자가 선정한 시뮬레이션 설계값**이다.
- 회전익 전환 완료가 속도 0 또는 안정된 호버링 도달을 뜻하지 않는다. 전환 후 필요한 잔여 감속·호버링 안정화 시간은 10초와 별도로 배정하되, 이 시간도 전체 최대 600초 안에 포함한다.
- 10초 안에 선택한 시작·종료 속도가 가감속 제약을 지키며 연결되는지 확인한다. 연결할 수 없는 설정은 조정하거나 제외하며, 시간을 맞추기 위해 위치·속도를 순간 변경하거나 제약을 무시하지 않는다.
- 전환 중 선택 기동 금지는 그대로 유지한다. 이륙 측 20초·착륙 측 10초 규칙은 현재 전체 비행 생성 설정에 반영되어 있다. 기존 60초 진단 profile과 과거 실행 결과를 소급 변경하지 않는다.

VTOL의 ‘직선 상승 → 직선 순항 → 직선 하강’을 전체 비행으로 풀면 다음과 같다.

```text
0→80 m 수직 이륙·초기 상승 → 80 m 호버링 → 고도 유지·직선 전방 가속·순항 전환 20초
→ 500 m까지 직선 상승 → 500 m 직선 순항 → 직선 하강 → 수평 비행 회복
→ 직선 감속·호버 전환 10초 → 필요한 잔여 감속·안정화 → 호버링 → 수직 착륙·정지
```

## 6. 카탈로그와 실제 Episode의 구분

| 객체 | 기본 조합 | 개수 | 표시 방식 |
|---|---|---:|---|
| 고정익 | 상승 4 × 순항 4 × 접근 4 | 64 | 한글 기동 이름 |
| 헬기 | 상승 4 × 중간 6 × 접근 4 | 96 | 한글 기동 이름 |
| VTOL | 상승 4 × 순항 4 × 접근 4 | 64 | 한글 기동 이름 |
| 합계 | 세 객체의 기본 시나리오 카탈로그 | **224** | 실제 생성 개수가 아님 |

- 시나리오 ID는 움직임 조합을 나타낸다. Episode ID·dataset ID·run ID와 구분한다.
- 예: ‘선회 상승 → 원주비행 → 직선 하강’의 좌선회 상승과 우선회 상승은 같은 기본 조합의 다른 실행이다. 현재 seed는 출발 방향, 선회 방향, 속도 배율을 바꾼다. 반경과 지속시간을 각각 독립적으로 무작위 선택하는 방식은 아니다. 고정익 목표 고도는 300 m, 헬기·VTOL은 500 m다.
- 표시 이름은 `객체 · 상승 기동 / 중간 기동 / 접근 기동`처럼 읽을 수 있게 만든다. 예: `헬기 · 선회 상승 / 정지 후 재출발 / 직선 하강`.
- 카탈로그는 버전별 설정의 기동 목록에서 구성하고, ID와 사람이 읽는 이름을 함께 표시한다. 현재 설정 파일은 `data_generation/v1/configs/full_flight_settings.yaml`이다.
- 224종이라는 숫자만으로 학습 데이터가 충분하다고 판단하지 않는다. 단순 정상 비행과 각 기동의 진입·회복, 허용 강도·시간 범위를 확보해야 한다.
- 허용 속도·반경·목표 고도에서 600초 안에 연결되지 않는 설정은 조정하거나 제외한다. 시간을 강제로 압축하거나 위치를 이동해 완주한 것처럼 처리하지 않는다.
- 현재 생성기는 출발점으로의 복귀를 강제하지 않는다. 특정 착륙점에 도달하도록 하는 조건은 아직 정하지 않았다. 착륙점 조건을 정하면 접근·감속 거리를 포함해 경로를 구성해야 한다.

## 7. 현재 생성 설정과 해석

수치의 기준은 [전체 비행 설정 파일](../data_generation/v1/configs/full_flight_settings.yaml)이다. 아래 값은 질점 궤적을 생성하기 위한 설정이며, 실제 기체의 최소·최대 성능이나 실비행으로 확인한 안정 운용 범위가 아니다.

| 항목 | 고정익 | 헬기 | VTOL |
|---|---|---|---|
| 운용·순항 목표 고도 | 300 m | 500 m | 500 m |
| 초기 상승 경계 | 50 m까지 직선·+3° | 80 m까지 수직 상승 | 80 m까지 수직 상승 |
| 기본 수평 목표속도 | 30 m/s | 수평 이동 시 15 m/s | 고정익 비행 시 30 m/s |
| seed 적용 수평 목표속도 | 28.5~30 m/s | 14.25~15 m/s | 고정익 비행 시 28.5~30 m/s |
| 공중 최소 수평속도 설정 | 20 m/s | 호버링·정지 허용 | 고정익 비행 구간 20 m/s |
| 기본 선회율 설정 | 0.06 rad/s | 0.12 rad/s | 고정익 비행 시 0.06 rad/s |
| 상승·하강 설정 | 경로각 크기 최대 10°, 저고도 규칙 우선 | 선택 상승·하강의 기본 수직속력 4 m/s | 고정익 구간 경로각 크기 최대 10° |
| 착륙 측 접근 고도 | 100 m부터 직선·−3° | 40 m에서 수직 착륙으로 연결 | 80 m에서 호버 전환으로 연결 |
| 지면 부근 처리 | 10 m에서 flare로 연결 | 10 m에서 저속 착륙으로 연결 | 10 m에서 저속 착륙으로 연결 |

표의 속도와 선회율을 모든 시점에 강제하지는 않는다. 진입·회복 때는 이전 상태에서 부드럽게 바꾸며, 호버링·지상 정지·전환 구간에는 해당 단계의 속도를 사용한다. 선회 반경도 속도와 선회율에 따라 달라지므로 따로 무작위 추출하지 않는다.

헬기·VTOL의 수직 이륙 목표속력은 3 m/s다. 수직 착륙은 기본 2 m/s로 내려오다가 지상 10 m 구간에서 1 m/s로 감속하고, 접지·정지까지 부드럽게 연결한다. 헬기의 착륙 접근 고도 40 m는 현재 생성 설정이며, 초기 이륙 고도 80 m와는 다른 기준이다.

### 7.1 단계 연결과 시간

공통 설정은 수평 가속도 2.5 m/s², 접선 가속도 2 m/s², 수직 가속도 1 m/s², jerk 2 m/s³이다. 이 값들은 급격한 속도·방향 변화를 제한하기 위한 연구용 기준이다. Gazebo가 입증한 기체의 절대 한계로 해석하지 않는다.

내부 계산 간격은 0.02초, 저장 간격은 0.2초다. 기본 지상 정지와 호버링 유지시간은 각각 2초, 순항 유지시간은 40초다. 단계 연결시간은 별도로 포함하며, 제약을 만족하도록 늘어날 수 있다. 전체 시간은 이 과정을 모두 합쳐 최대 600초로 제한한다.

VTOL의 전환 목표는 이륙 측 20초, 착륙 측 10초다. 착륙 측 모드 전환이 끝나도 수평속도가 남아 있으면 추가 감속한 뒤 호버링과 수직 착륙으로 이어간다. 따라서 ‘전환 10초’와 ‘10초 뒤 완전히 정지’는 같은 뜻이 아니다.

### 7.2 아직 별도로 확인할 사항

설정 파일이 있다는 것과 모든 조합이 모든 seed에서 성공한다는 것은 다르다. 실제 완주 여부는 각 실행 결과로 확인한다. 실패한 조합을 시간을 압축하거나 상태를 순간 변경해 성공으로 처리하지 않는다.

특정 착륙점으로 돌아오는 경로, 실제 기체의 성능 보장, 정밀 접촉 동역학은 현재 범위에 포함하지 않는다. 과거 참조 계산의 수치와 현재 생성 설정이 다르면 어느 쪽 값인지 출처를 함께 적는다.

### 7.3 속도값을 선정한 근거

현재 생성기는 힘·추력에서 속도를 계산하는 Gazebo 동역학 모델이 아니다. 객체별 목표속도를 설정한 뒤, 가속도와 jerk 제한 안에서 연속적인 속도 곡선을 만드는 질점 운동학 모델이다.

| 설정 | 현재 값 | 근거와 한계 |
|---|---|---|
| 고정익·VTOL 고정익 구간의 기본 수평속도 | 30 m/s | 속도를 상향하자는 대화와 전환 진단에서 사용한 값을 전체 비행의 생성용 기본값으로 사용한다. 참조 모델에서 자동 추출한 최대 안정 속도가 아니다 |
| 헬기 기본 수평속도 | 15 m/s | 전환 진단에서도 사용한 생성용 기본값이다. 실측 헬기 속도 분포를 학습하거나 Gazebo 성능 상한을 그대로 옮긴 값이 아니다 |
| 속도 배율 | 0.95~1.0 | 같은 조합에서 속도를 조금씩 바꾸기 위한 설정이다. 이 범위를 실측 통계로 추정했다는 근거는 현재 확인한 설정·구현에 없다 |
| 수직속도·가감속·jerk | 7절과 7.1절의 값 | 기동 연결을 위한 생성용 설정이다. 개별 참조 시험 결과와 모든 시나리오에서의 성공을 구분한다 |

참조 기록은 [전환 진단](point_mass_transition_rules.md), 현재 실행 설정은 [full_flight_settings.yaml](../data_generation/v1/configs/full_flight_settings.yaml)을 따른다. 참조 진단의 총속력과 현재 설정의 수평속도는 같은 양이 아니므로 숫자가 같다는 이유로 동일 조건으로 취급하지 않는다.

### 7.4 seed로 속도를 정하는 시점

전체 비행 생성 함수는 Episode 시작 때 속도 배율 하나를 균등분포 `Uniform(0.95, 1.0)`에서 뽑는다. 같은 Episode의 상승·순항·하강은 이 배율로 정한 기본 수평 목표속도를 공유한다. 기동마다 또는 매 시점마다 새로운 속도를 뽑지 않는다.

```text
Episode seed → 속도 배율 1개 → 객체 기본 수평속도에 곱함
                            → 단계별 목표속도 설정 → 연속 가감속 곡선
```

예를 들어 배율이 0.97이면 고정익·VTOL의 기본 수평 목표속도는 29.1 m/s, 헬기는 14.55 m/s다. 이는 계산 예시이며 특정 seed의 실행 결과가 아니다. 헬기의 수직 이동·호버링에서는 수평 목표속도가 0이고, VTOL 이륙 측 전환의 목표속도는 별도 설정인 20 m/s다. 수직 이착륙 속도 역시 별도 설정을 사용하므로 배율을 모든 속도에 일괄 적용하지 않는다.

출발 방향과 선회 방향도 Episode 시작 때 선택한다. 가감속 제한 때문에 연결시간을 늘려 재시도할 때는 이미 뽑은 값을 재사용한다. 전체 조합 생성에서는 상위 seed로부터 Episode별 seed를 파생한다. 재현하려면 seed뿐 아니라 코드·설정·시나리오 지정 방식도 같아야 한다. 시나리오를 생략하면 난수로 조합을 고르는 과정이 추가되어 같은 seed라도 명시적으로 지정한 실행과 추출값이 달라질 수 있다.

구현 위치: [generate.py](../data_generation/v1/generate.py)의 조합별 seed 배정과 [full_flight.py](../data_generation/v1/full_flight.py)의 `run_full_flight_episode`.

### 7.5 목표속도에서 순간 속도와 위치까지

내부 상태는 수평속력 `v_h`, 부호 있는 수직속도 `v_z`, 선회율 `ω`로 구성한다. 목표가 바뀌면 이전 상태와 새 목표 사이를 다음 곡선으로 연결한다.

```text
u = 구간 시작 후 경과시간 / 연결시간     (0 ≤ u ≤ 1)
S(u) = 10u³ − 15u⁴ + 6u⁵
현재 값 = 시작 값 + S(u) × (목표 값 − 시작 값)
```

따라서 속도가 목표값으로 순간적으로 뛰지 않는다. 일반 연결시간은 최소 12초와 속도 차이에 필요한 가속도·jerk 시간을 비교해 정한다. VTOL 이륙 측 전환처럼 시간이 명시된 구간은 그 시간을 사용한다. 생성 후에는 전체 속도 벡터에서 계산한 가속도와 jerk를 검사한다. 검사에 실패하면 같은 난수값으로 연결시간 배율을 1.25배씩 늘려 최대 5회 시도한다. 시간·고도 조건 등으로 구성이 불가능하면 오류로 종료하며, 모든 오류를 재시도하는 것은 아니다.

고정익과 VTOL 고정익 구간의 수직속도 기준은 `v_h × tan(경로각)`이다. 여기서는 `v_h`가 수평속력이므로 `tan`을 사용한다. 총속력을 기준으로 한 `총속력 × sin(경로각)`과 혼동하지 않는다. 하강에서는 수직속도의 부호가 음수다. 헬기는 별도로 설정한 수직속도를 사용한다.

실제 상승·하강 유지속도는 목표 고도, 진입·회복 시간, 기동 지속시간을 함께 맞추면서 기준값보다 작아질 수 있다. 특히 나선 기동의 회전시간을 확보해야 할 때 수직속도를 낮출 수 있다. 즉, 최대 경로각 10°나 수직속력 4 m/s를 모든 시점에 고정하는 방식이 아니다.

선회율을 적분해 진행 방향 `ψ`를 구한 뒤, ENU 속도 벡터를 만든다.

```text
vx = v_h × cos(ψ)     # East 방향 속도
vy = v_h × sin(ψ)     # North 방향 속도
vz = v_z             # Up 방향 속도
총속력 = √(vx² + vy² + vz²)
```

이 속도 벡터를 사다리꼴 적분해 위치를 구한다. 선회에서는 수평속력이 같더라도 방향이 바뀌므로 가속도가 발생한다. 원주·나선의 선회율은 한 바퀴 회전과 설정 상한을 함께 만족하도록 계산하고, 진입·회복에서는 선회율을 부드럽게 바꾼다. 출력은 내부 계산 결과를 0.2초 간격으로 보간한다. 관측오차는 이 정답 궤적을 만든 뒤 위치에 추가하며, 오차가 있는 위치를 미분해 내부 속도를 만드는 것은 아니다.

구현 위치: [full_flight.py](../data_generation/v1/full_flight.py)의 `_Flight.segment`, `transition_time`, `altitude`, `maneuver`, `arrays`와 `_compile`.

### 7.6 속도 저장 파일과 컬럼

아래 경로는 생성 결과 폴더 `outputs/data_generation/v1/<dataset_id>/`를 기준으로 한다. 전체 비행 생성 경로에 대한 설명이며 과거 6-DOF 진단 컬럼과 구분한다.

| 파일 | 컬럼 | 의미·단위 |
|---|---|---|
| `evaluation/truth.csv` | `episode_id`, `step`, `t_s` | 원본 Episode·시점 번호·시간(s) |
| `evaluation/truth.csv` | `x_m`, `y_m`, `z_m` | 관측오차 없는 ENU 위치(m) |

| `evaluation/diagnostics.csv` | `track_turn_rate_rad_s` | 진행 방향의 선회율(rad/s) |
| `evaluation/diagnostics.csv` | `acceleration_mps2`, `jerk_mps3` | 내부 계산 간격에서 구한 벡터 크기를 보간한 값(m/s², m/s³) |

총속력은 별도의 `speed_mps` 컬럼으로 저장하지 않는다. `truth.csv`의 세 속도 성분으로 계산한다. 내부 간격과 저장 간격이 다르므로 diagnostics의 가속도 크기와 truth의 축별 가속도로 다시 계산한 크기는 정확히 일치하지 않을 수 있다. 수평속력도 스칼라 보간값과 보간된 두 속도 성분의 크기 사이에 작은 차이가 날 수 있다.

이 속도들은 검토·평가용 정답 정보다. 학습용 관측 CSV에 그대로 넣지 않으며, 관측 입력과 혼동하지 않는다. 저장 구현은 [dataset.py](../data_generation/v1/dataset.py)의 `_truth_rows`와 `_motion_diagnostic_rows`를 참고한다.

## 8. 결정 이력

아래는 결정 당시의 기록이다. 이후 변경된 값은 본문의 현재 규칙과 7절을 우선한다. 특히 초기의 양방향 전환 10초, 고정익 목표 고도 500 m, 속도 미확정 표기는 현재 설정과 구분한다.

| 순서 | 사용자 결정 | 반영 |
|---|---|---|
| 1 | 고정익·VTOL·헬기에 대해 지상 출발부터 착륙까지 최대 10분 | 공통 최대 600초, 출발·종료 고도 0 m |
| 2 | 상승·순항·접근마다 여러 종류를 섞지 말고 하나씩 선택 | 각 객체의 선택 기동 조합표 |
| 3 | 고정익 100 m까지 직선 상승, 이후 최대 10°, 저고도 3° 접근 | 고정익 전용 규칙, 300 m 선회 시작안 미채택 |
| 4 | 헬기도 이륙부터 착륙까지 시나리오별 정리 | 헬기 96종 및 공통 수직 이착륙 |
| 5 | VTOL 시나리오 정리와 전환 설명 정정 | 전환 중 전방 가속·감속은 포함 |
| 6 | 전환 중 상승·선회·S자 기동은 하지 않음 | 전환과 선택 기동의 겹침 제외. 64종 유지 |
| 7 | 세 객체를 문서 하나로 정리 | 이 문서 작성. 코드·UI·설정·기존 실행 결과 미변경 |
| 8 | VTOL 전환 시간 10초 제안 후 문서 업데이트 요청 | 양방향 각각 10초, 합계 20초. 호버링 안정화는 별도 배정하며 모두 최대 600초에 포함. 생성용 설계값으로 기록 |
| 9 | 헬기·VTOL 초기 이륙 고도를 100 m에서 80 m로 정정 | 0→80 m 수직 상승·초기 호버링으로 확정. 헬기는 이후 선택 상승 기동, VTOL은 80 m에서 순항 전환 10초 후 선택 상승 기동. 고정익 및 착륙 측 규칙은 변경하지 않음 |
| 10 | 순항 고도 500 m로 정해서 확인 | 세 객체의 중간 순항·수평 이동·체공 목표를 500 m로 고정. 초기 이륙 80 m, 고정익 저고도 100 m 규칙, 최대 고도 1,000 m는 보존. 시간 예산 계산과 전체 시나리오 실행을 구분 |
| 11 | 고정익 3° 상승은 50 m까지, 이후 최대 10°, 운용 고도 300 m 및 상승·하강·순항 속력 상향 | 고정익 상승 경계 100→50 m, 목표 고도 500→300 m로 대체. 30 m/s는 직전 대화에서 가져온 기본 후보이며 정확한 기본값은 미확정. 하강 경계 100 m·−3°, 다른 객체 조건은 유지 |

문서의 합의 출처는 현재 대화와 위에 연결한 프로젝트 문서다. 이 카탈로그는 항공 매뉴얼의 공식 분류를 그대로 옮긴 것이 아니며, 수치 제약 계산·실행 결과는 별도 기록과 연결한다.


## 9. 같은 움직임에서 학습 입력을 만드는 방법

위 조합표는 물체가 어떻게 움직이는지를 정한다. 관측오차와 객체 식별 여부는 그 궤적을 만든 다음 적용하므로, 움직임 조합 224종 자체는 바뀌지 않는다.

한 궤적에 위치 관측오차 σ=1·3·5 m를 각각 적용하고, 각 관측 궤적에서 식별 획득·항상 미식별·식별 상실 입력을 만든다. 따라서 원본 궤적 하나에서 학습 입력은 총 9종이 나온다. 식별 여부가 바뀌어도 위치 관측은 계속 유지한다.

같은 원본에서 나온 입력은 모두 같은 train·valid·test 분할에 둔다. 상세 컬럼, 식별 전환 시점, 저장 위치는 [현재 데이터 생성 방식](data_generation_current.md)과 [객체 식별 입력 명세](identity_training_inputs.md)를 참고한다.
