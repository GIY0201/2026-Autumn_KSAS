# Gazebo 계수 기반 최소 운동 제약 — 1차 계산

날짜: 2026-09-07  
상태: **공개 원본 계수 확인·독립 대수 계산 완료 / 생성용 운용 범위 확정·profile 적용은 미완료.**

## 1. 목적과 이번 정정

목적은 실기체의 정밀 재현이 아니라 질점 궤적에 사용할 최소 운동 제약의 근거를 얻는 것이다.

`고정 버전 Gazebo 모델·물리식 → 필요한 힘·가속 여력 계산 → 정상 기동용 운용 범위 선택 → 질점 생성기에 적용`

기존 고정익의 수직속도 1 m/s는 Gazebo 계산 결과가 아니라 Stage 1 테스트 설정이었다. [이전 초안](minimum_motion_constraints.md)의 기존 설정값 표는 채택안에서 철회한다. 기존 YAML은 재현을 위해 보존하며 자동 변경하지 않는다.

이번에는 Gazebo·PX4·WSL을 실행하거나 설치하지 않았다. 공개 XML을 읽어 계수를 추출하고, 별도 계산으로 아래 표를 얻었다. **Gazebo 실행 궤적, 6-DOF 재현, 실측 성능으로 표시하지 않는다.** 전체 내부 장치를 구현할 필요는 없지만, 어떤 힘을 생략한 계산인지는 표시한다.

## 4. 실제 계산 결과와 의미

### 4.1 쿼드콥터·VTOL의 추력 여력

모터가 설정 회전수에 도달했고 정상 회전 방향일 때 원본 모터 식의 추력 크기는 `T_i=k_i Ω_i²`다. `rotorVelocitySlowdownSim`은 표시/계산용 joint 회전수를 늦춘 뒤 힘 계산에서 복원하므로 최대 회전수를 다시 나누지 않는다.

`T_sum = Σ k_i Ω_i²`  
`Ω_hover = sqrt(mg / Σk_i)` — 동일 모터·동일 회전수, 수직 추력  
`a_z,zero-speed = T_sum/m − g` — 정지·수직 정렬, 추가 공력 무시

| 계산값 | X500 | Standard VTOL 회전익 모드 |
|---|---:|---:|
| 설정 회전 상한에서 수직 추력 N | 34.19432 | 180.00000 |
| 추력/중량 비 | 1.68911 | 3.65271 |
| 이상적인 hover 회전수 rad/s | 769.43257 | 784.84407 |
| 정지 시 최대 추력의 순수직 가속 여력 m/s² | **6.75790** | **26.01425** |

이 가속 여력은 정상 기동용 상한을 확정한 값이 아니다. 순간적으로 이 힘을 만들 수 있다는 계산과 안정된 기동을 얼마나 오래 유지하는지는 다르다. 특히 VTOL의 큰 값을 그대로 넣으면 사용자가 지적한 급격한 움직임이 다시 생길 수 있다.

최소 힘 제약의 후보는 다음과 같다. 저속·항력 무시·주추력만 고려한 경우:

`a_h² + (a_z + g)² ≤ (T_available/m)²`, `a_z+g ≥ 0`

여기서 `a_h=sqrt(a_E²+a_N²)`, `a_z=dv_z/dt`이며 Local ENU의 Up이 양수다. `a_z`는 중력을 포함한 관성계 순가속도이지 IMU specific force가 아니다.

수평 가속과 상승 가속이 같은 추력을 나눠 쓰므로 독립 최댓값을 동시에 주지 않는다. `T_available`은 순간 가용 추력이며 위 표의 설정 최대 추력을 넘지 않는다. 정상 운용에서는 기울기/추력 여유를 별도로 정한다. VTOL의 전진 모터 추력 **104.720105 N**을 수직 추력 180 N에 더하지 않는다. 전진 모터·날개가 기여하는 구간은 힘의 방향별 합으로 계산한다.

최대 수평속도·상승속도·하강속도는 이 추력 식만으로 정해지지 않는다. 특히 모터 plugin의 항력은 로터 축에 수직인 유속 성분에 작용한다. 수직 축 방향 비행의 유한한 속도 상한을 이 항력식만으로 만들 수 없다. 기존 0.75/0.4/8/2 m/s를 새 모델에서 도출한 값으로 채택하지 않는다.

### 4.2 고정익·VTOL 주익의 양력 조건

조종면 중립·sweep 없음·실속 전 원본 식은 `CL=cla×alpha_effective`, `CD=|cda×alpha_effective|`다. `alpha_effective`에는 SDF의 `a0`가 포함되며, 기체 자세각 또는 비행 경로각과 같지 않다.

`CL_peak = cla × alpha_stall`  
`L = 0.5 ρ V² S CL`  
`V_support = sqrt(2mg / (ρ S CL_peak))`

`V`는 이 계산의 전체 대기속도이며, 무풍에서 전체 지상속력과 같다. 수평속력 `v_h`와 구별한다.

| 계산값 | RC Cessna | Standard VTOL 주익 |
|---|---:|---:|
| 중립 주익 `CL_peak` | 1.61187752 | 1.61187752 |
| 주익만으로 중량을 지지하는 경계 속력 m/s | **2.65174** | **7.12600** |
| 전진 모터의 설정 최대 추력 N | 12.00000 | 104.720105 |

**2.65174와 7.12600을 이륙속도·운용 최소속도로 등록하지 않는다.** 최대 CL에서 주익 양력만 중량과 같다는 경계 계산이다. 꼬리날개 힘, 조종면, 추력 방향, 모멘트 평형, 이착륙 여유는 빠져 있다. 이 값을 정상상태 비행시험으로 표시하지 않는다. 실제 항공기 전체를 복원하지 않고도, 질점에서 이 지지 경계보다 높은 속력에 별도의 운용 여유를 둘 수 있다.

정상 정속 수평 선회에서는 `L_required=mg/cos(φ)`로 필요 양력이 커지고, 같은 CL 한계의 경계 속력은 `V_support/sqrt(cos(φ))`가 된다. `φ`는 협조선회의 등가 bank다. source의 `alpha_stall`을 bank 제한으로 잘못 쓰지 않는다. bank·하중 여유의 정상 운용값은 아직 확정하지 않았다.

### 4.3 고정익 상승: 1 m/s 대신 조건부 계산

계산 가능성을 확인하기 위해 **주익만 포함하는 간소화 정상 힘 평형**을 18조건에서 계산했다: Cessna/Standard VTOL × 전체 속력 10/15/20 m/s × 경로각 0/3/10도. 이 속력들은 시험 지점이며 새 운용 범위가 아니다.

가정: 무풍, 정속 직선, 중립 조종면, 주익 실속 전, 주익 외 공력·모터 횡항력·모멘트 평형 생략, 추력을 경로 방향으로 근사. 완전한 Gazebo 힘 계산의 이식이 아니다.

이 시험에서는 회전 운동이 없고 선택한 주익 plugin들의 `a0`·forward/upward가 같아 동일한 `alpha_effective`와 동압을 가정한다. 따라서 아래 area 가중 비율로 합산할 수 있다. 회전·다른 조종면 입력으로 각 surface의 국소 유속이나 유효 받음각이 달라지면 surface별 힘을 계산해 합해야 한다.

`L_required = mg cos(γ)`  
`D_wing = L_required × [Σ(S_i cda_i) / Σ(S_i cla_i)]`  
`T_required = D_wing + mg sin(γ)`  
`w = V sin(γ)`; 수평속력을 입력한다면 `w = v_h tan(γ)`

| 시험 지점 | 계산 수직속도 m/s | Cessna 필요 추력 N | VTOL 주익 모드 필요 전진 추력 N |
|---|---:|---:|---:|
| 전체 속력 15 m/s, 3도 | 0.78504 | 4.54199 | 9.22337 |
| 전체 속력 10 m/s, 10도 | 1.73648 | 6.47773 | 15.10948 |
| 전체 속력 15 m/s, 10도 | 2.60472 | 6.47773 | 15.10948 |
| 전체 속력 20 m/s, 10도 | 3.47296 | 6.47773 | 15.10948 |

18조건 모두 **이 간소화 식 안에서는** 요구 CL이 `CL_peak`보다 작고 필요 추력이 모터 설정 최대값보다 작았다. 이는 ‘1 m/s가 Gazebo에서 계산된 고정 상한’이라는 해석을 지지하지 않는다. 각 속도로 실제 궤적을 생성해 추종에 성공했다는 뜻도 아니다.

같은 경로각에서 속도가 달라도 위 필요 추력이 같은 이유는 실속 전 `CL`·`CD`를 모두 alpha에 선형 비례시키는 현재 주익 식 때문이다. 필요한 양력에 맞춰 alpha를 조정하면 이 계산의 L/D가 일정해진다. 따라서 이 단순화 식에서 무리하게 최대 속도를 역산하지 않는다. 생성용 최대 속력은 별도 운용 설정으로 정해야 한다.

### 4.4 헬기: 블레이드 양력에서 출발

실제 include인 `rotor_head_cw`에는 주로터 LiftDrag 두 개가 있다. 중립 offset 0, `cla=6.1`, `alpha_stall=0.2`이므로 실속 분기 경계의 `CL=1.22`다.

두 블레이드의 공력 작용점 속력이 모두 `U`이고, 두 양력 벡터가 모두 수직 위쪽이라고 단순화하면:

`T_rotor = 2 × 0.5 ρ U² S_blade CL`  
`U_support = sqrt(mg / (ρ S_blade CL_peak)) = 28.50645 m/s`

**28.50645 m/s는 헬기의 전진속도가 아니라 블레이드 공력 작용점의 속력**이다. 유도 유입·플래핑·주기 피치·모멘트 균형은 생략했다. 실제 rotor RPM이나 기체 속도로 바꾸려면 작용점의 회전축 기준 거리·방향·유입을 함께 계산해야 한다.

본체 SDF의 회전 명령 multiplier 500이나 JointController의 `cmd_max=10`을 기체 최고속도로 쓰지 않는다. 이 자료만으로 헬기 속도 40 m/s, 상승률 4 m/s가 확인됐다고 말할 수 없다. 주로터의 가용 합력을 얻은 뒤 수평·수직 가속의 결합 조건으로 축약하는 방식은 가능하다.

## 5. 질점에 남길 최소 제약 항목

| 객체 | 모델 계수에서 얻는 조건 | 생성용으로 별도 선택할 항목 |
|---|---|---|
| 고정익 | 속력·경로각·선회에 따른 필요 양력/추력, 실속 전 분기 확인 | 운용 속력 범위, bank/하중 여유, 진입·회복 가속 변화율 |
| 쿼드콥터 | 가용 추력과 중력을 고려한 수평·수직 가속 결합 | 정상 기울기/추력 여유, 수평속력·상승/하강속력, 전환 완만함 |
| VTOL | 회전익 추력 조건 + 주익 양력 조건 + 전진 추력, 방향별 합력 | 전환 중 양력 분담, wing 진입 여유, 정상 운용 속력·전환시간 |
| 헬기 | 블레이드 계수·국소 유속으로 계산한 주로터 합력 조건 | rotor 운용점·단순화 범위, 정상 기울기, 수평/수직 속력·전환 완만함 |

오른쪽 항목은 정밀 실비행 검증을 기다려야 한다는 뜻이 아니다. **어떤 정상 움직임을 생성할지 선택하는 설계값**이며 출처 기반 계산과 함께 명시하면 된다. 다만 아직 선택하지 않은 값을 기존 테스트 YAML에서 가져와 Gazebo 근거라고 부르지 않는다.

모든 객체에서 속력·선회·가감속은 결합한다. 수평 운동이면 `a_h²=(dv_h/dt)²+(v_h ω)²`, 정속 선회이면 `R=v_h/|ω|`다. 정지에서는 track 반경을 정의하지 않는다. 위치·속도 연속성과 기동 진입·회복을 유지한다.

지상 0m 출발·착륙 정지, 최대 600초, 최대 고도 1000m, 고정익 100m까지 직선 3도/그 위 최대 10도·저고도 접근 −3도, 단계별 기동 하나라는 사용자 규칙은 그대로다. 경로각과 시간 규칙을 Gazebo에서 도출했다고 표시하지 않는다. 최대 고도는 도달 필수 목표가 아니다.

## 6. 확인 범위와 다음 적용 순서

- 공개 commit·XML 계수·plugin 수식을 확인했고, 주익 중량 지지식과 hover 추력식의 역대입 및 18개 주익 힘 평형 조건을 계산 assertion으로 확인했다.
- 이번 계산은 명시한 단순화의 대수 계산이다. 동역학 적분, 6-DOF trim, Gazebo 실행, 실제 기체 검증은 하지 않았다. 이전 X8 9/14 추종 판정도 이번 계산의 합격 기준이 아니다.
- 이번 산출물은 이 문서의 표다. 신규 dataset/CSV, 생산 코드·YAML 수정, 의존성 설치, 서버 재시작, Git commit/push는 하지 않았다.
- 다음에는 **고정익부터 정상 운용 속력·선회 여유를 정하고 속력–경로각–선회 조합표를 만든다.** 그때 힘 여력과 사용자 시나리오 규칙을 함께 적용한다. 네 객체를 한 번에 임의 상한으로 채우지 않는다.

재계산 방법: 2절의 고정 원본 XML에서 3절 항목을 읽고 link 질량을 합산한 뒤 4절 식에 넣는다. 주익은 Cessna 네 plugin, VTOL 두 plugin이며 꼬리날개는 제외한다. 계산용 g, 공기밀도, 생략 항목, 전체/수평 속력 구분을 유지해야 같은 표가 나온다.
