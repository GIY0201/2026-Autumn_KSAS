# 예측 모델 설계 인계와 기존 기준의 차이

기록일: 2026-09-07  
출처: 별도 작업 **예측 모델 설계 논의** (`01a07733-d316-75b1-b110-6ad8e251dbd8`)의 인계. 마지막 학습·평가 제안에 대한 사용자 승인 “좋아 그렇게 하자”와 해당 제안을 이 작업에서 읽기 전용으로 확인했다.  
상태: 큰 모델 방향은 별도 작업에서 합의됨. 상세 수식·hyperparameter·schema는 미확정이며 구현 승인은 아님.

## 1. 기존 문서와의 관계

[기존 연구 기준](../동적_공중_객체_미래_점유영역_설계.md)과 GRU 도식은 수정하지 않고 보존한다. 아래는 최신 인계 합의를 누락하지 않기 위한 변경표다. 기존 기준의 통합·전환 적용과 새 코드 배치는 아직 수행하지 않았다.

| 항목 | 기존 GRU 기준 | 최신 작업의 합의 |
|---|---|---|
| 미래 표현 | 대표 경로 하나 | RED-SDS 기반 여러 경로 표본 |
| 관측 불확실성 | 경로 주변의 오차 범위 | 과거 관측 해석에서 반영해 미래 분포까지 전달 |
| 점유 영역 | 대표/기동 확장 회랑 | 시점별 중심 표본 voxel 빈도의 current/outer |
| 기동 처리 | 최근 가속도 극값, 최대 3초 확장 | 움직임의 지속·전환을 확률 모델로 학습하는 방향 |
| 유지하는 시간·크기 | 3초·16개 → 15초·75개, 7 m cube | 동일 |
| 정답 사용 | 평가 전용 | 평가 전용; 학습 target/보조 loss에도 미사용 |

두 방법을 섞어 “기존 모델 그대로”라고 표현하지 않는다. 이 문서의 current/outer는 예전 `occupancy_v2` 계약을 도입한 것이 아니다. 새 모델 코드를 기존 `models/gru/v1/`에 넣지 않으며, 아직 새 모델 폴더는 만들지 않는다.

## 2. 합의된 입력·출력

- 온라인 입력: 최근 3초, 5 Hz의 3D 관측 위치 16개·각 timestamp·장치/추적기가 제공하는 해당 관측의 위치 불확실성.
- 불확실성은 실제 정답과의 순간 차이가 아니다. 최대 한계·표준편차·공분산·확률구간은 구별한다.
- 출력 목표: 미래 0.2~15.0초, 0.2초 간격 75개 중심 위치를 가진 여러 경로 표본.
- 매 0.2초 새 관측에 맞춰 예측을 갱신한다. 이는 처리시간 목표이지 이미 달성한 결과가 아니다.
- 위치 m, 시간 s, 운동/출력 3D를 유지한다. 공통 좌표는 부모 작업에서 초반에 선택한 Local ENU(x=East, y=North, z=Up)다. 원점·원본 변환·모델 상대좌표/회전·시간 정렬 상세는 미확정이다.
- 원본 RED-SDS를 기준으로 필요한 관측 모델 변경을 분리한다. 추가 GRU/Transformer·state-dependent hazard·mode-age 보정·물리 전이 강제는 기본 모델 문제를 확인한 뒤 검토하는 후순위 후보이다.

2026-09-07 인계 보완: 앞서 이 문서가 좌표축까지 미확정이라고 적은 것은 부모 작업의 초반 선택 누락이었다. ENU를 새로 채택한 것이 아니며, 직접 확인한 기록은 [결정 대조표 D03](decision_reconciliation.md)에 있다. 별도 모델 작업에서 아직 받지 못했던 정보와 프로젝트 전체에서 미정인 정보를 구분한다.

## 3. current·outer의 의미

별도 작업에서 합의한 초기값은 voxel 한 변 1 m, current 목표 확률량 30%, outer 95%, 객체 크기 7 m × 7 m × 7 m이다.

각 미래 시점에서:

1. 경로 표본의 해당 시점 중심 위치를 같은 크기 voxel에 모아 표본 빈도를 센다.
2. 동일한 밀도 순서로 선택하여 누적 표본 비율 30% 이상과 95% 이상의 중심 영역을 만든다.
3. 두 중심 영역에 동일한 7 m 정육면체 크기를 반영해 점유 영역을 만든다. outer는 current를 포함한다.

30%·95%는 크기 반영 전 모델 중심 분포의 목표다. voxel 단위 선택으로 실제 담긴 표본 비율은 목표를 넘을 수 있다. 상위 경로 30%를 고르는 것이 아니며 outer가 나머지 70%만을 뜻하지도 않는다. 떨어진 덩어리 사이의 빈 공간을 자동으로 채우기로 합의하지 않았다.

표본 수, 동일 빈도 voxel의 tie-break, 격자 원점·경계 처리·cube 확장의 voxel 반영 방식은 미확정이다. 실제 중심 포함률, 객체 크기 반영 후 포함 여부, 시간별 포함률, 전체 15초 경로의 동시 포함 여부는 서로 다른 지표다. 95%는 실측 포함률·안전 보장이 아니다.

## 4. 관측 불확실성과 정답 경계

합의: 장치 불확실성을 관측 해석에 넣고 그로 인한 상태 불확실성을 미래 분포로 전달한다. 동일한 장치 오차를 마지막에 다시 일괄 더하지 않는다. 고정 객체 크기 반영은 별개다.

인계에서 확인한 원본은 [REDSDS src/model.py](https://github.com/abdulfatir/REDSDS/blob/74885285e825ecf8a3aaf9b68df802b22f5cebdb/src/model.py), commit `74885285e825ecf8a3aaf9b68df802b22f5cebdb`이다. 원본은 emission likelihood와 관측 출력 중심이며, 장치별 불확실성을 받는 전용 연결을 그대로 제공하지 않는다는 점이 인계됐다. 이 작업에서도 원본 URL을 읽기 전용으로 확인했지만 코드는 실행하지 않았다.

따라서 원본 emission 표본이나 평균을 센서오차가 분리된 실제 중심 분포라고 곧바로 부를 수 없다. 다음을 상세 설계해야 한다.

- 장치 불확실성을 likelihood/inference에 넣는 위치와 수식.
- 알려진 관측 불확실성과 학습할 나머지 불확실성의 구분·식별 가능성.
- 실제 중심 분포라는 출력 의미와 확인 방법.
- 불확실성의 좌표/단위·축 간/시간 간 상관, 변환 가정, 누락/유효하지 않은 입력 처리.
- 관측오차를 생성하는 설정과 예측기에 공개하는 불확실성 정보의 일관성.

정답 위치는 평가에만 쓴다. 학습 target이나 보조 loss로 쓰려면 별도 설계 합의가 필요하다. 입력 파일에 함께 존재한다는 이유로 정답·명령·잠재 상태·실제 오차 실현값을 학습기에 넘기지 않는다.

## 5. 학습·평가 합의

- 학습은 긴 연속 관측 궤적과 관측 불확실성으로 움직임의 지속·전환을 학습한다.
- 실제 추론/평가에는 최근 3초·16개 관측만 제공한다. 긴 학습 시퀀스를 평가 조건으로 통째로 주지 않는다.
- 원본 `forward`의 `context_length` 처리를 고려해야 한다. 파일만 길게 만들면 긴 학습이 구현된다고 가정하지 않는다.
- 미래 실제 위치 포함률, 점유 영역 부피, 기동 변화 뒤 반응, 전체 처리시간을 함께 평가한다.
- 모드 수·latent dimension·Encoder·duration·optimizer·학습량·시퀀스 길이·표본 수·합격선은 미확정이다.
- 기동/원본 Episode 단위로 데이터를 분할한다. 합성 pilot의 train/validation/test는 물체 종류별 70/15/15이며 X8 원본 TRAIN/VALIDATION과 별개다. 합성 예측 성능과 실측 일반화는 별도로 보고한다.
- 부모 작업의 생성 Episode는 60초·5 Hz·301개 시점, 표형 데이터 CSV다. 저장 길이가 곧 모델 학습 context 길이라는 뜻은 아니다.
- 초반 학습 무작위 구간·validation/test 고정 구간 선택을 유지한다. RED-SDS의 긴 관측 학습에 맞는 추출 길이·방법과 평가 시작점을 상세화하며 16개 입력 학습으로 자동 고정하지 않는다.
- 학습 모델을 선택하고 평가에서는 지정 checkpoint manifest로 모델·입력 축·형식을 식별하는 방향을 유지한다. 자동 최신 선택이나 차원 불일치의 조용한 변환은 금지한다.
- 공개 물체 정보는 known/unknown을 구분하고 오식별은 후속이다. optional profile은 첫 RED-SDS 입력으로 자동 채택하지 않는다.

X8 실측 단편의 길이 제약과 첫 생성 범위는 [생성 설계 3절](data_generation_v1_design.md)을 따른다. 실측 기동 재현용 자료와 장시간 합성 학습 자료를 동일한 검증 증거로 취급하지 않는다.

## 6. 후속 통합 설계에서 결정할 일

1. 위 최신 합의를 기존 기준 문서에 어떤 범위로 반영할지 설명하고 전환 이력을 남긴다. 기존 GRU를 비교 기준으로 실제 구현할지도 자동 결정하지 않는다.
2. 이미 합의한 ENU·60초/5 Hz·CSV·합성 70/15/15를 바탕으로 원점·변환·시간 정렬·불확실성·파일/접근 경계 등 남은 계약을 정한다.
3. RED-SDS 원본 보존 범위와 관측 해석/실제 중심 출력에 필요한 변경을 식·입출력·테스트 단위로 명세한다.
4. 긴 학습 시퀀스/짧은 추론 context, 표본 수·voxel tie·평가 합격 기준을 정한다.
5. 그 후 명시적인 구현 승인을 받아 코드·환경·실험을 시작한다.

이 문서는 인계 기록과 전환 검토표다. 최종 상세 구현 명세가 모두 확정되었다거나 모델 구현·학습·성능 검증이 완료되었다고 표현하지 않는다.
