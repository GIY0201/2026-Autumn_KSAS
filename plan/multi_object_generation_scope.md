# VTOL·쿼드콥터·헬기 생성 확대

날짜: 2026-09-07.  
상태: **추가 대상·v1 통합 승인 / 구현 진행 중**.  
직접 출처: 사용자의 “좋아 그럼 VTOL이랑 쿼드콥터 헬기 이렇게 하자”. 기존 X8을 유지하면서 세 종류를 추가하는 것으로 해석한다. 이 문서는 구체적인 기체·계수의 채택이나 구현 완료 기록이 아니다.

**후속 정정:** 사용자가 “그렇게 해야지. 굳이 내부 장치는 의미가 없잖아”라고 승인했다. VTOL·헬기에 대해서는 아래의 내부 장치·힘/모멘트 전체 재현 선행 조건을 적용하지 않고 [간소화 운동모델 범위](reduced_motion_v1_implementation.md)를 따른다. 자료로 확인한 운동 특성과 시뮬레이션 가정을 구분하고 연속 궤적을 생성한다. 기존 X8·Crazyflie는 변경하지 않는다. 아래 원문 감사와 최초 full-dynamics 제안은 과거 판단 근거로 보존한다.

## 1. 범위

완료 목표는 각 객체를 8088 UI에서 선택하고, seed로 새 데이터를 생성한 뒤 XY/XZ/YZ/3D로 재생할 수 있는 상태다. 논문 조사나 UI 이름 추가만으로 완료 처리하지 않는다.

| 대상 | 서로 구별할 운동 | 현재 상태 |
|---|---|---|
| X8 고정익 UAV | 기존 직진·속도 변화·선회·상승·하강 | 기존 v1 유지 |
| VTOL | 호버링, 수직 이동, 고정익 순항으로 전환, 순항, 역전환 | 추가 대상 확정; 기체 형식·전체 계수 미채택 |
| 쿼드콥터 | 네 로터 추력에 의한 호버링·가감속·정지·수직/수평 이동·선회 | 추가 대상 확정; 대표 기체·계수 검토 |
| 헬기 | 메인로터 collective/cyclic과 tail rotor에 의한 호버링·전진·선회·상하 이동 | 추가 대상 확정; 일반 단일 메인로터+테일로터형으로 해석, 대표 기체·전진 비행 근거 검토 |

여기서 VTOL은 수직이착륙이 가능한 모든 항공기를 묶는 상위 용어가 아니라 **고정익 순항 모드로 전환하는 기체**의 작업상 분류다. 헬기는 쿼드콥터의 질량/속도만 바꾼 모델로 만들지 않는다. 각 분류는 처음부터 모든 기체를 대표한다고 주장하지 않고 근거를 확보한 대표 기체 하나에서 시작한다.

유지할 기존 합의:

- 3D Local ENU, 위치 m·시간 s, 연속 60초, 5 Hz, 시작점 포함 301개 시점.
- 새 합성에는 독립 ambient wind를 넣지 않는다. 원본 비행이 무풍이었다고 가정하거나 공력·유도유동을 제거한다는 뜻은 아니다.
- Episode당 단일 객체, 빈 공간, 객체 간 상호작용·지형·회피 제외.
- 시점/축 독립 Gaussian 위치 관측 sigma 1/3/5 m, public 관측과 evaluation truth/명령/내부 상태 분리.
- 특정 센서·GPS·카메라·실제 탑재·예측기 구현은 추가하지 않는다.
- 8088만 사용하고 새 port나 fallback listener를 만들지 않는다.
- 학습/평가 분할은 기존 Episode 단위 원칙을 유지한다. 대량 pilot 발행을 이번 대상 선정과 동일시하지 않는다.

기동 목록은 지원 목표다. 선택한 모델의 검증 범위를 벗어나면 구현 전에 제한을 밝힌다. 모든 60초 Episode에 전체 이착륙 절차를 억지로 압축하거나, 실측 구간을 이어 붙여 새 연속 운동이라고 부르지 않는다. 지면 접촉·착륙장치 충격을 추가하지 않고 초기에는 공중 운동 구간을 다룬다.

## 2. 현재 확인한 공개 근거와 채택 제한

### VTOL

- Rohr, Stastny, Verling, Siegwart (2019), *Attitude- and Cruise Control of a VTOL Tiltwing UAV*. DOI `10.1109/LRA.2019.2914340`. [저자 원문](https://arxiv.org/abs/1903.10623).
- 논문은 tiltwing의 운동모델과 hover/transition/cruise 실비행 시험을 보고한다. **3D 구현에 필요한 계수 전체·원본 로그·코드 재현까지 확보했다는 뜻은 아니다.** tiltwing을 Lift+Cruise 기체와 섞지 않는다.
- 2D numerical transition 예제와 timestamp가 없는 CSV의 한계는 기존 [VTOL 검토](vtol_source_review.md)를 유지한다. 후보가 있다는 이유만으로 실측 기반 VTOL 생성 완료로 표시하지 않는다.

### 쿼드콥터

- Eschmann, Albani, Loianno (2024), *Data-Driven System Identification of Quadrotors Subject to Motor Delays*. 저자 arXiv에 IROS 2024 accepted로 표시돼 있다. 인용 식별자 `10.48550/arXiv.2404.07837`은 **arXiv DOI**다. [논문 v2](https://arxiv.org/html/2404.07837v2), [공식 코드·로그 저장소](https://github.com/arplaboratory/data-driven-system-identification).
- 실제 비행 자료에서 관성, 추력 곡선, 토크 계수, motor delay를 식별하며 Crazyflie와 큰 쿼드콥터를 각각 다룬다. 공식 저장소의 `logs_crazyflie`, `logs_large`와 재현 notebook 항목을 확인했다. 각 로그의 무결성·단위·채택할 기체 구성은 아직 감사하지 않았다.
- [RotorPy](https://github.com/spencerfolk/rotorpy)는 계산 구현 후보로 남긴다. 다만 [현재 Crazyflie parameter 파일](https://github.com/spencerfolk/rotorpy/blob/main/rotorpy/vehicles/crazyflie_params.py)에 일부 drag 설정이 가정값이라는 주석이 있어, 전체 기본값을 실측 계수라고 간주하지 않는다. 실측 식별 근거와 모델의 생략/가정을 분리한다.

### 헬기

- Navaneethkrishnan B, Biswas, Saksena, Anand, Omkar (2018), *State-Space Identification of Unmanned Helicopter Dynamics using Invasive Weed Optimization Algorithm on Flight Data*. arXiv DOI `10.48550/arXiv.1809.05021`. [저자 원문](https://arxiv.org/abs/1809.05021), [전체 논문](https://arxiv.org/pdf/1809.05021).
- Align TREX 550 실비행을 이용한 계수 식별 근거는 있지만, 시험은 **일정 RPM의 hover 조건**이다(PDF 3쪽). 검증도 일부 회전 상태를 중심으로 보고한다(PDF 4쪽). 이 모델만으로 일반 전진·선회·넓은 속도 범위가 검증됐다고 할 수 없다.
- NASA의 [UH-60 모델 보고서](https://ntrs.nasa.gov/citations/19840015585) 메타데이터에는 전체 parameter 설명이 있으나, 이번 환경에서는 원문 PDF가 403으로 열리지 않았다. 원문 계수나 재현성을 확인한 것으로 처리하지 않는다. 소형 TREX와 UH-60 계수를 혼합하지 않는다.
- 따라서 **hover 국소 모델로 전체 헬기 생성기를 대신하지 않는다**. 전진/선회까지 지원하는 대표 기체의 근거를 확인하거나, 지원 범위를 명시적으로 좁힌 뒤 채택해야 한다.

이번 조사에서 원문·저자 페이지와 공식 코드를 확인했다. Google Scholar 전용 검색으로 새 두 논문의 직접 일치 결과를 확보하지 못해 저자 arXiv와 공식 저장소를 사용했다. 인용 확인과 모든 계수의 실측 검증은 다른 상태다.

## 3. 승인된 연결 구조 — v1 통합

후속 사용자 지시: “새 세객체도 V1에 통합해줘. 그 외에는 너가 얘기한대로 작업하자”. 아래의 기존 v2 분리 제안은 이 지시로 대체한다. X8 운동식과 기존 출력은 보존하고 개발 중인 v1의 객체 지원을 확장한다.

```text
객체별 원본/논문 + 출처가 명확한 기체 계수
    → 객체별 운동모델 + 제어/기동 명령
    → 연속 truth 궤적
    → 기존 관측오차 합성 및 CSV 계약
    → 객체·버전·seed·출처를 기록한 새 dataset
    → 같은 8088 UI에서 명시 선택·생성·재생
```

권장 방식은 공통 실행·저장·재생 계층과 객체별 동역학을 분리하는 것이다. 위치를 직접 그리는 공통 질점 모델에 이름만 바꾸는 방식은 기존 합의와 맞지 않는다. 세 개의 독립 웹 서버를 만드는 방식은 포트·UI·저장 규칙을 중복시키므로 사용하지 않는다.

현재 코드에서 확인한 영향:

- `data_generation/v1/dataset.py`는 X8 simulation record와 X8 출처를 직접 사용한다. 기존 writer를 그대로 호출하면서 identity label만 변경하면 잘못된 출처를 기록하게 된다.
- `contracts/v1/validation.py`의 공개 위치/시간/오차 열과 `identity_label` 검사는 기체별 계수를 담지 않는다. 같은 의미·열을 유지하면 **contracts/v1을 재사용할 수 있다**. 객체가 추가된다는 이유만으로 계약 버전을 일괄 증가시키지 않는다.
- 현재 UI service의 출력 검증은 generator v1을 전제로 한다. 새 생성 버전과 데이터 형식 버전을 분리해 검증하고, 미지원 조합은 거부해야 한다.

승인된 배치:

- `data_generation/v1/`: 기존 X8 물리를 유지하고 새 객체의 운동모델·설정·테스트를 같은 버전 안에서 분리. 공통 결과 저장기는 객체별 출처와 고유 diagnostic을 보존하며, X8 계수를 다른 기체로 쓰지 않음.
- `contracts/v1/`: 공개 CSV 의미를 유지하는 동안 재사용. 새 열/의미가 꼭 필요할 때만 별도 계약 변경을 제안.
- `visualization/v1/`: 객체별 실제 지원 설정을 명시적으로 선택하는 통합 UI. 물리 계산은 수행하지 않으며 실행 주소는 같은 8088. 기존 dataset 재생을 유지.
- `data_sources/<source_id>/`, `outputs/data_generation/v1/<dataset_id>/`, `outputs/visualization/v1/<run_id>/`: 기존 원본/산출물 배치 원칙 적용. 실제 확보·실행 때만 생성.

v2 폴더를 만들지 않는다. 공통 지침 AGENTS.md는 자동 변경하지 않고 이 계획과 README로 결정/상태를 안내한다. 구체적인 작업 순서와 실행 상태는 [v1 통합 구현 계획](multi_object_v1_implementation.md)을 따른다.

## 4. 구현 착수와 완료 기준

각 기체를 착수하기 전에 식·계수·단위·좌표·입력 채널·적용 범위·출처 버전의 대응표를 만든다. 미확인 항목을 임의 상수로 채우지 않는다. 계수의 실측 근거, 모델의 단순화, 다양한 명령을 위한 실험 설계를 분리한다.

세 객체는 각각 다음을 통과해야 한다.

1. 채택 근거와 지원 비행 범위를 명시하고, 제공된 검증 사례 또는 원본 운동 응답을 재현한다. 공개 원본 부재 시 그 한계를 숨기지 않는다.
2. 힘/모멘트·좌표 부호·hover/trim, 비유한 상태, actuator 제한과 수치 수렴을 확인한다. 근거가 좁은 모델을 범위 밖으로 조용히 외삽하지 않는다.
3. 기동 전환에 위치·속도·자세를 초기화하지 않고 여러 seed의 60초 궤적을 생성한다. 실패 Episode는 완료 데이터로 내보내지 않는다.
4. public-only 경계, source/parameter/code hash와 seed 추적, 재실행 시 결과 보존을 검사한다.
5. 8088에서 객체 선택 → 실제 생성 → 진행/중단 → 결과 열기 → 네 보기 재생을 실행 검증한다. 기존 X8 회귀 검사도 통과한다.

하나의 객체가 통과하면 그 객체만 `사용 가능`으로 표시할 수 있다. 전체 세 종류의 완료와 개별 전달을 구분한다. 과학적 타당성은 그래프 표시나 software test 통과만으로 보장되지 않는다.

## 5. 최초 대상 선정 시점의 기록

- 세 종류를 추가 대상으로 기록하고 공개 근거의 범위를 점검했다.
- 코드·계수·UI 선택지·서버·port·원본 데이터는 변경하지 않았다. 새 생성·학습·수치 테스트도 실행하지 않았다.
- Grok `second-opinion`을 공개 논문 설명만으로 시도했지만 로그인되지 않아 실행되지 않았다. 프로젝트 파일은 보내지 않았고 외부 검토 완료로 표시하지 않는다.
- 이후 변경: 사용자가 v1 통합 구현을 승인했다. 이 절의 미변경/미실행 기록은 최초 조사 시점이며 현재 구현 상태는 별도 실행 계획에 기록한다.
