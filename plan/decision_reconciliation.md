### Pilot 규모를 읽는 방법

- 12:29:37 `profile_balance`: 동일하게 생성, 12:33:41 `pilot_size`: 총 400개를 선택했다. 당시 목표는 Bird/Quadrotor/VTOL/Fixed-wing 각각 100개였다.
- 이 4종 pilot 규모·균등 구성은 초기 확대 목표로 기록을 보존한다. 현재 첫 범위는 X8이므로 네 종류를 한꺼번에 구현하거나 X8만 400개로 변경하지 않는다.
- X8 첫 전달의 재현·소량 생성 확인과 4종 pilot 전체 발행을 구분한다. X8을 기존 고정익 100개 몫에 대응시킬 구체적인 배치/발행 계획은 후속 전달 단위에서 명시한다. 기존 400개 합의를 통째로 잊고 생성량을 처음부터 다시 묻지 않는다.
- 4종 확대 pilot은 물체 종류마다 70 train/15 validation/15 test, 합계 280/60/60이다. 이 합성 분할과 공개 X8 TRAIN 13개/VALIDATION 4개는 다른 분할이다.

`학습 무작위 구간`은 최신 RED-SDS가 16개 관측만으로 학습해야 한다는 뜻이 아니다. 원본 Episode는 60초로 보존하고, 긴 관측 시퀀스의 학습 context 길이와 추출 방법은 모델 인계의 별도 미확정 항목이다. 평가에는 최근 3초·16개 관측만 제공한다.

### 기록이 서로 충돌할 때

1. 사용자 선택과 그 이후의 명시적인 변경을 먼저 대조한다.
2. 문서에 없다는 이유만으로 대화에서 확정한 것을 미확정으로 바꾸지 않는다.
3. 오래된 assistant 제안이나 예시 수치를 사용자 확정값으로 승격하지 않는다.
4. 후속 변경이 특정 항목만 바꿨다면 나머지 합의는 유지한다.
5. 이 표를 갱신한 뒤 관련 설계 절·폴더 지침·README의 같은 상태 표현을 함께 수정한다. 코드 구현이나 기준 모델 변경 승인을 추론하지 않는다.

## 4. X8 전달 이후 확대 요청 — 2026-09-07

- 사용자: “좋아 그럼 VTOL이랑 쿼드콥터 헬기 이렇게 하자”. 이번 추가 대상은 **VTOL·쿼드콥터·헬기**이며 기존 X8은 유지한다.
- 과거 Bird/Quadrotor/VTOL/Fixed-wing 4종 논의는 당시 기록으로 보존한다. 새 요청에 없는 조류를 이번 구현 범위에 자동으로 포함하거나, 과거 400개 pilot 발행을 완료한 것으로 취급하지 않는다.
- 세 객체의 실제 운동모델 기반 생성과 8088 UI 연결이 목표다. 특정 기체/계수 채택, v2 파일 배치, 생성기 검증은 아직 완료되지 않았다.
- 현황·출처 점검과 연결 구조 제안은 [세 객체 확대 기록](multi_object_generation_scope.md)을 따른다. 기존 ENU·시간축·관측오차·public/evaluation·출력 보존 결정은 유지한다.
- 이 추가 기록은 대상 합의를 보존한다. 기존 AGENTS.md의 자동 변경이나 원본·코드·UI 선택지 변경을 수행한 것은 아니다.

### 후속 구현 승인 — 같은 v1

- 사용자: “새 세객체도 V1에 통합해줘. 그 외에는 너가 얘기한대로 작업하자”.
- VTOL·쿼드콥터·헬기를 `data_generation/v1`과 `visualization/v1`에 통합한다. 이전 v2 분리 제안은 채택하지 않는다. `contracts/v1`, ENU·시간축·관측오차·public/evaluation, 8088, 기존 X8 결과 보존은 유지한다.
- 구현은 승인됐지만 미확인 물리 계수를 임의 값으로 채우거나 hover-only 모델을 전체 비행 검증으로 표현하는 승인은 아니다. 객체별 원문 근거와 software 검증을 분리해 기록한다.

### 후속 범위 정정 — 내부 장치가 아닌 객체 운동 특성

- 사용자: “그렇게 해야지. 굳이 내부 장치는 의미가 없잖아”. 직전 설명의 실제 자료 → 운동 특성 → 간소화 모델 → 새 연속 궤적 흐름을 승인했다.
- VTOL·헬기는 로터·모터·관성·stabilator 제어기의 완전한 복제를 요구하지 않는다. 속도·가감속·선회·수직 이동과 VTOL의 hover/순항 전환을 표현하는 간소화 운동모델을 v1에 추가한다.
- 실제 자료에서 확인한 범위와 시뮬레이션용 응답·명령·제한 설정을 명확히 구분한다. 내부 계수가 없다는 이유로 생성 연결을 계속 보류하지 않는다. 다만 raw-log 식별 또는 실비행 재현을 수행한 것처럼 표현하지 않는다.
- 기존 X8·Crazyflie 구현 및 결과는 보존한다. 같은 ENU/60초/5Hz/관측오차/출력 계약과 8088 UI를 유지한다.
- 새 상세 범위와 실행 기록: [간소화 운동모델 통합](reduced_motion_v1_implementation.md). 기존 힘/모멘트 전체 재현 체크리스트는 이번 VTOL·헬기의 선행 조건이 아니다.

## 5. 질점 수치의 참조 모델 활용 승인 — 2026-09-07

- 사용자: 기존 6-DOF에서 운동 수치를 추출해 질점 모델의 근거로 사용하자는 설명에 “좋아. 그렇게 하자”로 승인했다. 같은 요청의 PX4 질문은 추가 참조 모델의 활용 가능성 조사이며 설치·교체 승인과 구분한다.
- 기존 X8 6-DOF 및 controller를 보존하고 오프라인 시험에서 정상 직선, 가감속, 좌우 선회, 선회 진입·회복·반전, 상승·하강과 선회 복합 운동의 실제 시뮬레이션 반응을 추출한다. 최종 연구용 합성 궤적은 새 질점 엔진이 생성한다.
- 속도별 선회율·반경, 접선·횡·수직 가속도, 경로각, 반응·정착 시간과 미수렴/실패 조건을 함께 기록한다. 입력 명령과 달성 상태, 기체 모델과 controller의 영향, 공중 기동과 미지원 지상 이착륙 범위를 구분한다.
- 기존 코드의 속도 검사 범위·bank 명령 제한을 실측 성능 한계로 승격하지 않는다. 단일 최댓값을 전 조건에 적용하지 않고 시험 조건과 결합된 결과로 관리한다. 수치 보정과 비교 시험 조건을 분리하며, 원본 held-out 자료를 보정에 사용하지 않는다.
- [질점 전환 1단계](point_mass_stage1_plan.md)의 엔진·계약·UI 작업과 후속 수치 추출/보정을 구분한다. 수치 추출을 수행하기 전에는 현재 profile을 6-DOF 조건 시험으로 검증했다고 표시하지 않는다. 이 기록 시점에 신규 수치 추출 시험은 미실행이다.

### PX4 참조 모델 조사 — 도입 미확정

- 현재 공식 문서의 Gazebo 모델 목록에는 고정익, X500 quadrotor, Standard VTOL, Quad Tailsitter, Tiltrotor가 있다. PX4의 airframe/controller 설정과 시뮬레이터의 동역학 모델은 동일한 자료가 아니다. [Gazebo Vehicles](https://docs.px4.io/main/en/sim_gazebo_gz/vehicles)
- PX4 내부 SIH도 물리 모델을 제공한다. 다만 공식 main 문서는 quadrotor 외 fixed-wing/VTOL 등을 experimental로 분류하고 비현실적 운동 가능성을 경고한다. 빠른 실행을 실비행 충실도의 근거로 쓰지 않는다. [SIH Simulation](https://docs.px4.io/main/en/sim_sih/)
- 헬기 제어 지원은 experimental이며, 위 Gazebo/SIH 기본 모델 목록에서 일반 헬기 시뮬레이션 모델은 확인되지 않았다. 제어 가능한 airframe이 있다는 사실만으로 데이터 생성용 동역학 모델이 준비됐다고 주장하지 않는다. [Helicopters](https://docs.px4.io/main/en/frames_helicopter/)
- PX4를 채택할 경우 기체 유형·PX4 버전·모델 commit·계수 출처와 검증 범위를 먼저 고정한다. 시뮬레이터 참값의 위치·속도로 운동 특성을 추출하며, 추정기 출력이나 simulated IMU specific force를 그대로 궤적의 참값/관성 가속도로 취급하지 않는다.
- 후보 활용 방식은 별도 참조 시험 → 운동 특성 표 → 기존 질점 profile 보정이다. PX4 전체를 질점 runtime에 넣거나 PX4 직접 생성 궤적을 질점 생성 결과로 재명명하지 않는다. GPS·영상 인식 연구를 추가하지 않는다.
- 이번 조사는 read-only 문서 확인이다. PX4/Gazebo 설치·실행·추가 통신 port 개방·현재 8088 viewer 교체를 수행하지 않았다. 실제 도입 전 환경과 통신 port 사용/종료 방침은 별도로 확정한다.

### 후속 승인 — Gazebo 참조 데이터 및 헬기 후보 확인

- 사용자: “이걸 사용해서 고정익·쿼드콥터·VTOL 모델의 데이터를 뽑자. 그리고 내가 기억하기론 Gazebo에도 헬기 모델있는걸로 알아 그거확인해봐”. 이어서 [ArduPilot 헬기 자료](https://discuss.ardupilot.org/t/helicopters-in-gazebo/136332)를 제공했다. 위의 도입 미확정 상태에서 **Gazebo를 통한 참조 데이터 추출 방향 승인**으로 변경한다.
- PX4 공식 모델의 첫 후보는 RC Cessna, X500, Standard VTOL이다. Gazebo에서 수집한 조건별 운동 반응을 질점 profile의 보정 근거로 사용한다. 이전 질점 생성 결정이나 현재 1단계 범위를 취소한 것이 아니다.
- 헬기는 PX4 기본 목록 밖의 ArduPilot/SITL_Models PR #149에서 확인했다. T-Rex 450 기반 1.75배 모델이며 로터 기구·공력·제어 연결이 있다. 2026-09-07 현재 모델 PR과 필요한 Gazebo 수정 2건은 미병합이다. 소형 RC 기반 결과를 모든 헬기의 실제 성능으로 일반화하지 않는다.
- 기존 WSL은 Ubuntu 26.04이며 실행 PATH에서 Gazebo를 찾지 못했다. 별도 Ubuntu 24.04 WSL 준비는 제안 상태로 남기고, 신규 배포판·패키지 설치 전에 사용자 확인을 받는다. 8088 viewer와 기존 환경은 보존한다.
- 공개 소스 확인·현재 환경 점검은 수행했지만 설치·Gazebo 실행·데이터 수집·질점 수치 보정은 미실행이다. 상세 근거와 실행 전 조건은 [Gazebo 참조 데이터 도입 기록](gazebo_reference_data_design.md)에 남긴다.

### 후속 정정·구현 승인 — 독립 Python 참조 함수

- 사용자는 실제 PX4 연결이 아니라 수치 추출이 목적임을 다시 명시했고, 기존 Python 참조 모델에 조건별 수치 추출 함수를 추가하는 설명에 “좋아 그렇게 해야지”로 승인했다.
- 기본 실행 경로를 **기존 X8 Python 동역학·시험용 제어 → 조건별 운동 수치 CSV → 검토 후 질점 profile 보정**으로 정정한다. PX4·Gazebo 전체 실행 및 WSL 설치는 진행하지 않는다. Gazebo 식·계수는 필요한 객체의 별도 참조 후보로만 남긴다.
- 첫 구현은 고정익 X8 수치 추출이며 기존 동역학·controller·질점 구현·8088 UI를 변경하지 않는다. 시험 명령·시간·보고용 tolerance는 설정으로 분리하고, 모델의 실측 계수나 실제 성능 한계로 표현하지 않는다.
- 수치 적분·물리 상태 및 입력/실제 응답 기록은 필요하다. 계산 결과를 실비행 검증으로 표시하거나 미수렴 시험을 정상 성능으로 채택하지 않는다. production profile 자동 보정·덮어쓰기는 이번 범위가 아니다.
- 명세와 실행 기록: [독립 X8 수치 추출](x8_characterization.md).
- 첫 실행 완료: 기존 Python X8로 14조건·각 36초 참조 CSV를 생성했고, code/Python 독립 검토 및 최종 통합 회귀 226개가 통과했다. hold 목표 허용오차 충족은 9/14이고 미충족 5조건은 그대로 표시한다. 이는 Gazebo 모델 이식·실비행 검증·질점 profile 수치 보정 완료를 뜻하지 않는다. 결과 UUID·조건별 판정·hash는 위 실행 기록을 따른다.

### 후속 정정 — Gazebo 계수 기반 최소 제약, 정밀 재현 확대 제외

- 사용자는 최소 제약을 만드는 것이 목적이라고 정정했고, 기존 수직속도 1 m/s가 Gazebo에서 확인한 값인지 지적했다. 해당 값은 Stage 1 테스트 설정이며 Gazebo 도출값이 아니다.
- 이후 “다시 작업 이어서 해줘”로 Gazebo 모델의 계수·식에 근거한 수치 정리를 재개했다. 기존 설정값 표를 새 제약 채택안으로 쓰지 않는다. [이전 초안](minimum_motion_constraints.md)은 철회 표시와 함께 보존한다.
- 현재 흐름은 공개 원본 계수·식 → 필요한 독립 계산 → 정상 기동용 운용 범위 선택 → 질점에 적용이다. Gazebo/PX4/WSL 전체 실행, 장치·센서·정밀 제어기 재현은 추가하지 않는다.
- 이번에는 네 모델의 원본 계수와 추력·주익/블레이드 양력 기반 조건부 수치를 계산했다. 전체 기체 운동의 실행 검증이나 생성용 최대 속력·상승률 확정과 구별한다. [계산표와 한계](gazebo_minimum_constraints.md)를 따른다.
- 원본 모델 수치, 간소화 계산 결과, 생성용 설계값, 사용자 시나리오 합의를 별도로 기록한다. 기존 source 정체성·profile·60초 데이터 계약·8088 viewer·기존 결과는 변경하지 않는다.
